# AGENTS.md

Rasp Hide — расширение Chrome (MV3) для скрытия пар на ro-rasp.tpu.ru. Стадия: v1.0.0 и v1.1.0 (вид занятия, фон клетки, hover, хранение частями, пакет для CWS — PLAN.md фаза 9) тегированы; v1.1.1 (новые иконки, картинки витрины в `store/`, фиксы скрытия) — первая публикация в Chrome Web Store. Remote — `origin` на GitHub. Релизные правки — через фича-ветку от `dev`, новая версия = новый тег.

## Документация — источник истины

Читать в этом порядке, требованиям не противоречить:

- `docs/REQUIREMENTS.md` — контракт v1.0 (поведение, инварианты, ограничения CWS)
- `docs/ARCHITECTURE.md` — структура файлов и реализация (в т.ч. схема DOM сайта)
- `docs/PLAN.md` — фазы разработки, git-процесс, согласованные решения (§3 — решения согласования)
- `docs/STORE_CHECKLIST.md` — обязателен к прогону перед релизом/сабмитом в CWS
- `docs/STORE_LISTING.md` — тексты формы CWS; `PRIVACY.md` — политика конфиденциальности (URL для формы)

Код, не соответствующий докам, считается ошибкой: docs фиксированы, их не менять без явного запроса пользователя.

## Жёсткие ограничения (CWS-модерация)

- Только MV3; `permissions` ровно `["storage"]`; **без** `host_permissions` (для `content_scripts.matches` не нужен; сеть не используется вообще)
- Запрещены `eval()`, `new Function()`, строковые `setTimeout`/`setInterval`, внешние скрипты/удалённый код (в т.ч. в CSP)
- Все DOM-элементы расширения — с префиксом `rh-*`; никакой обфускации; код читаемый

## Ключевые согласованные решения (из PLAN.md §3)

- Название пары для матчинга — **только видимый** `span.textContent`; fallback на `span.title` (расшифровка во всплывашке) не использовать. Вид занятия — так же только видимый текст `<b>` (ЛК/ПР/ЛБ), не `title`
- Правило = предмет + преподаватель + вид (`null` — «любой»); инварианты строятся на `covers(a, b)` в `lib/rules.js`; пересекающиеся правила допустимы, «Вернуть» снимает все скрывающие — при нескольких с подтверждением
- Набор правил хранится частями (`rules`, `rules_1..3`): изменение набора в `storage.onChanged` проверять через `R.hasRulesChange`, не `changes.rules`
- Фон полностью скрытой клетки — снять инлайновый цвет пары (не подставлять свой): подсветку текущего дня `.cur-day` рисует сайт
- Пара с несколькими преподавателями — **одна** пара, скрытие **поблочное**; `<hr>` уходит/возвращается вместе со своим блоком **только в режиме «плейсхолдер»**; в режиме «зачеркнуть» `<hr>` и фон клетки не трогаются никогда
- Единая логика правил в `lib/rules.js` (дубликаты, поглощение «у всех» с подтверждением, «уже покрыто», лимит 100, `lastError` → «Не удалось сохранить»); hover-меню и options не дублируют её
- UI-язык — русский хардкодом, без `chrome.i18n`
- Бейдж: per-tab, зелёная цифра-счётчик (включая «0»), серый «OFF»; текст «ON» не используется

## Тесты

- `npm test` = `node tests/{matcher,rules,content,background,options,suggestions,ui,popup,manifest}.test.js` по очереди; без фреймворка, CI гоняет то же самое (`.github/workflows/ci.yml`, Node 22)
- `npm run pack` — архив для CWS в `dist/` (список файлов выводится из манифеста, `scripts/pack.js`)
- Один файл: `node tests/matcher.test.js`
- `content/matcher.js` и `lib/rules.js` — DOM/chrome-свободные (или под мок); при изменении логики правил тесты правятся в том же коммите, не постфактум
- Линтера/тайпчека нет — проверка только тестами + ручная проверка на реальном сайте (распакованное расширение)

## Git-процесс (PLAN.md §0)

- `main` — только релизы; `dev` — интеграция; фича-ветки от `dev`
- Merge `--no-ff`; релиз: `dev → main` + тег `vX.Y.Z`
- Коммиты русские, префиксы `feat:` / `fix:` / `docs:` / `chore:`
- `.gitignore`: `.DS_Store`, `node_modules/`, `*.log`, `.idea/`, `.vscode/`, `Thumbs.db`, `.agents/`, `skills-lock.json`, `dist/`
