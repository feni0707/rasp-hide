## 2. Доменная модель

```ts
interface Rule {
  subject: string;          // видимое короткое название (нормализованное)
  teacher: string | null;   // null = «у всех», иначе ФИО
  type: string | null;      // вид занятия: 'ЛК' | 'ПР' | 'ЛБ' | …; null = «все занятия»
  enabled: boolean;
}

interface Settings {
  enabled: boolean;         // глобальный тумблер
  style: 'placeholder' | 'strike';
  rules: Rule[];
}
```

Хранение: `chrome.storage.sync` (ключи `enabled`, `style` и набор правил частями —
`rules`, `rules_1`, `rules_2`, `rules_3`, см. ниже).
Дефолт: `enabled: true`, `style: 'placeholder'`, `rules: []`.

Правило v1.0 без поля `type` — то же, что `type: null` («все занятия»): `sanitizeRule`
дописывает `type: null` при чтении, миграция хранилища не нужна.

**Хранение частями** (`RULE_KEYS`, `chunkRules`, `rulesFromStorage`, `hasRulesChange`).
Квота `sync` — 8192 байта на ключ (ключ + JSON значения в UTF-8), а правило с кириллицей
занимает ~90–110 байт: сотня в один ключ не помещается. Набор раскладывается по частям
не больше `CHUNK_BYTES` (7400) с сохранением порядка; первая часть — прежний ключ `rules`
(данные v1.0 читаются как есть). `saveRules` пишет **все** части одним `set`: запись
атомарна, а пустые старшие части затирают «хвосты» прежнего, более длинного набора.
Если набор не раскладывается в 4 части, `saveRules` не пишет ничего и возвращает
`ok: false` («Не удалось сохранить»). Подписчики `storage.onChanged` проверяют изменение
набора через `hasRulesChange(changes)`, а не `changes.rules`; content script читает
тумблер, стиль и все части одним `get` и собирает набор `rulesFromStorage`.

Отдельно — `chrome.storage.local`, ключ `suggestions`: `{ subjects: string[], teachers: string[] }`.
Это кэш увиденного на страницах расписания для подсказок при ручном вводе, а не настройка:
поэтому `local` (не переносится между устройствами) и отдельный модуль `lib/suggestions.js`.

Инварианты набора правил (поддерживает `lib/rules.js`, едины для hover, popup и options).
Основа — отношение **покрытия** `covers(a, b)`: правило `a` скрывает всё, что скрывает `b`
(тот же предмет; преподаватель и вид у `a` те же или «любые»; само себя правило не покрывает).

- Нет дубликатов (`keyOf`: `subject + teacher + type` после нормализации) — при попытке: «Правило уже существует» + [Включить существующее].
- Поглощение: добавление/включение правила удаляет включённые правила, которые оно покрывает. Чистая функция `wouldAbsorb(rule, rules): Rule[]` используется всеми местами изменения; удаление — всегда с подтверждением и списком удаляемых.
- Уже покрытое включённым правилом (`getCovering`) не добавляется и не включается: «Уже покрыто…» + [Включить существующее].
- Пересекающиеся правила («Матан — Иванов» и «Матан (ЛК) — все») допустимы: ни одно не покрывает другое. Поэтому возврат пары снимает **все** скрывающие её правила (`findRulesToRestore`), при нескольких — после подтверждения.
- `ruleMatchesPair(rule, {subject, teacher, type})` — скрывает ли правило пару; определено через `covers` (пара — «правило» с конкретными признаками). `matchRule` в `content/matcher.js` обязан давать тот же ответ — это сверяет тест на сетке правил и пар.
- Лимит 100 правил; `chrome.runtime.lastError` при записи → «Не удалось сохранить» (данные не теряются). `lastError` только читается — снимает его рантайм после возврата из коллбэка.
- `formatRule(rule): string` — единственное место, где собирается подпись «Предмет — Фамилия И. О.» / «Предмет (ЛК) — все преподаватели» (вид — как его пишет сайт; без вида скобок нет).
- `PAIR_TYPES` (ЛК — лекции, ПР — практики, ЛБ — лабораторные) и `typeLabel(type)` — подписи видов для меню, списка и формы; незнакомый вид подписывается своим кодом.

Формат файла экспорта (`serializeRules` / `parseRulesExport`):

```json
{ "format": "rasp-hide-rules", "version": 2, "exportedAt": "…ISO…", "rules": [ … ] }
```

`version` — версия структуры файла, не расширения: 2 — у правила есть `type`. Файлы
версии 1 читаются как есть (вид — «все занятия»). При разборе принимается и голый
массив правил (файл могли собрать руками); записи, не проходящие `sanitizeRule`,
отбрасываются, а не роняют импорт.

Матчинг преподавателя — по видимому ФИО (пользователи видят «Фамилия И. Я.»), id `/user_...` не используется — осознанный компромисс, пересмотр возможен в будущих версиях.

## 3. Content script

### 3.1. Чистая логика (`matcher.js`)

DOM-свободные функции (принимают NodeList/DOM-like интерфейс — для тестов мок):

- `splitIntoPairs(cellChildren): Node[][]` — группировка детей клетки на «пары»:
  - старт пары: `<div>`, содержащий `<b>` (тип ЛК/ПР/ЛБ) **или** (только если группа ещё не начата) `<span>` с названием;
  - `<hr>` прикрепляется к текущей паре;
  - остальные `<div>` (преподаватель, аудитория) — в текущую пару;
  - элементы расширения (`rh-placeholder`) в структуру пар не попадают.
- `splitPairIntoBlocks(pair): Element[][]` — разбиение пары на «блоки» преподавателей, разделённые `<hr>`: первый элемент пары (div с названием/типом) — «шапка», в блоки не входит; пара вида `[шапка, Преп1, <hr>, Преп2]` → блоки `[[Преп1], [<hr>, Преп2]]` (`<hr>` принадлежит следующему блоку и скрывается вместе с ним).
- `getBlockTeacher(block): string | null` — ФИО первого `a[href="/user_..."]` в блоке; `null`, если преподавателя в блоке нет.
- `normalize(text): string` — trim, схлопывание пробелов и `&nbsp;`; реэкспорт из `lib/text.js` (там же его берёт `lib/rules.js` — нормализация обязана быть одна на оба модуля).
- `isRhElement(el): boolean` — элемент интерфейса расширения (плейсхолдер, hover-кнопка, меню); в структуру пар не попадает. Класс `rh-strike` — стиль на элементах самой пары, а не UI расширения, поэтому такие элементы не отбрасываются.
- `isPlaceholder(el): boolean`, `childIndex(cell, el): number`, `placeholdersForPair(cell, pair): Element[]` — общая работа со структурой клетки; используются и `content.js`, и `ui.js` (раньше — двумя копиями в каждом).
- `getPairName(pair): string | null` — видимое короткое название из первого `<div>` пары (`span.textContent`, у мероприятий — `textContent` ссылки `a[href^="/event/"]`); если в первом `<div>` только вид (`(<b>ПР</b>)`, так выводятся элективные дисциплины по физкультуре), название берётся из следующего `<div>` без преподавателя; `null`, если названия нет (ОВ/ОС) → пара не скрываема.
- `getPairType(pair): string | null` — вид занятия: видимый текст `<b>` шапки («ЛК»/«ПР»/«ЛБ»; на сайте — `Название (<b title="Лекция">ЛК</b>)`); `null`, если `<b>` нет. `title` не используется — как и для названия.
- `getPairTeachers(pair): string[]` — все видимые ФИО из ссылок `href="/user_..."` всей пары (для hover-меню — пункт на каждого преподавателя); уникальны; пустой массив, если преподавателей нет.
- `matchRule(name, teacher, rule, type = null): boolean` — точное совпадение `name === rule.subject` (после normalize), преподаватель (`rule.teacher === null` — «у всех», иначе точное ФИО блока/пары) **и** вид (`rule.type === null` — «все занятия», иначе точный вид пары). Пара без известного вида не матчится правилом с видом. Матчинг пары с несколькими преподавателями выполняется **поблочно** в `content.js` (см. 3.2); вид у всех блоков пары общий.
- `isCellFullyHidden(cell): boolean` — все пары клетки скрыты (для решения по фону); вызывается только в режиме `placeholder` — в режиме `strike` фон клетки не трогается никогда.

### 3.2. Применение (`content.js`)

- Загрузка настроек (тумблер, стиль и все части набора правил одним `get`, см. §2) → прогон по всем `#raspisanie-table td.cell`; для каждой пары — название, вид (`getPairType`) и преподаватели блоков.
- Скрытие пары: `display: none` на всех элементах пары + вставка плейсхолдера-элемента (см. `ui.js`).
- Поблочное скрытие пары с несколькими преподавателями (`ПР Преп1 <hr> Преп2` — это **одна** пара): каждый блок (`[Преп N ...]` после `<hr>`) проверяется правилом независимо. Скрытый блок в placeholder-режиме → `display:none` + плейсхолдер «скрыто» после блока; в strike — класс `rh-strike` на элементы блока. «Шапка» пары (div с названием/типом) скрывается, **только если скрыты все блоки** — тогда ставится одна «скрыто» на всю пару, а не по одной на блок.
- `<hr>` скрывается/восстанавливается вместе со **своим** блоком (идущим после него) только в placeholder-режиме (фикс «старой полосы»); в strike-режиме `<hr>` **не** трогается.
- Плейсхолдеры синхронизируются идемпотентно (`syncPlaceholders`): лишние удаляются, недостающие вставляются; повторный прогон не дублирует их.
- Фон клетки: если все пары скрыты → инлайновый фон пары **снимается** (`removeProperty('background-color')` и `'background'`), и клетку красит сам сайт как пустую: белым, в столбце текущего дня — `.cur-day { background-color: #e8f5e9 !important }`. Подменять фон своим цветом (`transparent`, как в v1.0) нельзя: инлайн с `!important` перебивает подсветку дня. Иначе — восстановить исходный `style` (сохраняется в `WeakMap` при первом скрытии; исходный атрибут `style` кэшируется **до** любых изменений).
- `MutationObserver` на `document.body` (childList + subtree) с дебаунсом ~120 мс — повторное применение при перерисовке/расшифровке.
- `chrome.storage.onChanged` → переприменение без полной перезагрузки; при `enabled: false` — полный откат (см. 3.4) и `{type:'off'}` в SW.
- Счётчик скрытых пар текущей страницы (скрытые блоки/пары) → `chrome.runtime.sendMessage({type:'count', value})` (в SW для бейджа).
- Названия пар и ФИО из прогона запоминаются в `chrome.storage.local` для подсказок в настройках (`lib/suggestions.js`); запись — только при реальном изменении набора, ошибки записи молчаливы (это удобство, а не данные пользователя). При выключенном тумблере прогона нет — и сбора нет.

### 3.4. Полный откат (глобальный OFF)

- По `chrome.storage.onChanged` (`enabled: false`): снимается запланированный дебаунсом прогон, удаляются все `rh-*` элементы (плейсхолдеры, hover-кнопки, меню) и класс `rh-cell`, исходные стили восстанавливаются из `WeakMap`, hover-UI не работает (правила добавлять нельзя). Никакого «полускрытого» состояния. Дополнительно `processCells` сам молча выходит при `enabled: false` — страховка от прогона, запланированного до выключения. Каждая вкладка откатывается сама и сама чинит свой бейдж (`{type:'off'}`).

### 3.3. Hover-UI (`ui.js`)

- Для каждой пары (кроме пар без названия) создаётся overlay-кнопка «Скрыть» (position: absolute внутри td; td получает класс `rh-cell` с `position: relative` — именно класс, а не инлайн-стиль, иначе служебное свойство попадало бы в кэш «исходного» стиля клетки и оставалось после полного отката).
- **Показ и скрытие** (REQUIREMENTS §11.8). Обработчики одни на страницу (`mouseover`, `mouseout` с `relatedTarget === null` — уход за пределы окна, `click`, `keydown`). Активна не больше одной пары (`active`); показ другой — через `SHOW_DELAY_MS` (120 мс, отложенный показ `pending` не сбрасывается движением внутри той же пары). Решение по каждому `mouseover` — чистая функция `pointerAction({onPair, sameAsActive, hasActive, inActiveCell, menuOpen})` → `refresh | hold | leave | switch | idle` (тестируется в Node):
  - курсор в клетке активной пары (пара, кнопка, меню, отступы) — `hold`/`refresh`, таймер скрытия снимается;
  - ушёл из клетки — `leave`: кнопка скрывается через `HIDE_DELAY_MS` (300 мс), открытое меню — через `MENU_HIDE_DELAY_MS` (1000 мс); запущенный таймер не перезапускается последующими движениями, иначе меню при движущемся курсоре не исчезло бы никогда;
  - открытое меню не уступает соседней паре той же клетки (`hold`).
  Ошибка v1.0: кнопка и меню не входили в «зону» пары, поэтому уход курсора с кнопки не обрабатывался, а при открытом меню скрытие пропускалось вовсе — UI висел до клика или Escape.
- Клик → кастомное мини-меню: у пары с одним преподавателем — 2 пункта («Скрыть: ФИО» / «у всех») + «Отмена»; у пары с несколькими преподавателями — **отдельный пункт «Скрыть: ФИО» на каждого преподавателя** пары + «у всех» + «Отмена»; у пары без преподавателя — один пункт «Скрыть пару» (эквивалент «у всех»). Меню — DOM-элемент внутри клетки, закрывается по клику вне, Escape и уходу курсора (см. выше).
- Если у пары есть вид, под названием — переключатель `rh-menu-scope` из двух кнопок с `aria-pressed`: «Только <вид>» (по умолчанию) / «Все занятия». Состояние — `c.scopeAll`; переключение меняет только `aria-pressed` (меню не перерисовывается, фокус не теряется). Пункты создают правило с `type: c.scopeAll ? null : pm.type`.
- Поглощение при «Скрыть у всех»: через `wouldAbsorb` из `lib/rules.js`; при непустом списке меню превращается в подтверждение «Также удалится: …» ([Удалить] / [Отмена]).
- Скрытая пара: вместо содержимого — плейсхолдер «скрыто» (бледный, занимает место). Hover на плейсхолдер → кнопка «Вернуть» → `restorePair({subject, teachers, type})`: для блока — его преподаватель, для пары целиком — преподаватели всех блоков. Одно скрывающее правило снимается сразу; несколько (пересечение) — `status: 'confirm'`, меню показывает «Вернуть — значит удалить правила: …» и повторяет вызов с `confirmed: true`.
- Метаданные пары у контроллера (`c.pm`) обновляются на каждом прогоне: блоки и скрытость меняются, а контроллер (ключ — узел шапки) живёт дольше.
- Все добавленные элементы имеют префикс-класс `rh-*` и удаляются/пересоздаются при повторном прогоне.

## 4. Background (service worker)

- `chrome.action.onClicked` **не** подписывается: у действия есть `default_popup`,
  и клик уходит окну. Тумблер живёт в popup и в команде `toggle-hiding`
  (`chrome.commands.onCommand`, по умолчанию `Alt+Shift+H`). `commands` — ключ
  манифеста, не разрешение: `permissions` остаётся `["storage"]`.
- Бейдж — per-tab (`chrome.action.setBadgeText({ tabId, text })`), право `tabs` не требуется:
  - `{type:'count', value}` от content script → зелёная цифра (в т.ч. «0») для `sender.tab.id`;
  - `{type:'off'}` → серый «OFF» для `sender.tab.id`;
  - `chrome.tabs.onUpdated` — очистка бейджа вкладки при начале навигации; если это снова расписание, content script выставит счётчик.
- Текст «ON» не используется: цвет + цифра его заменяют.
- `chrome.runtime.onMessage` — только приём `{count|off}`.
- Никакой сети. `onInstalled` — инициализация дефолтных настроек, если их нет.

## 4a. Popup

Основная поверхность: тумблер, состояние текущей вкладки, список правил с поиском,
добавление вручную (раскрывается по кнопке), вид скрытой пары, переход на полную
страницу настроек.

- Состояние вкладки берётся из текста бейджа (`chrome.action.getBadgeText` для
  `tabs.query({active:true,currentWindow:true})`): это ровно тот счётчик, который
  уже прислал content script, и читается он без права `tabs`. Чистая функция
  `pageStateText(enabled, badge)` собирает законченную фразу.
- Раскладка: шапка и подвал закреплены, прокручивается только середина. Тогда
  закреплённые полосы физически не могут перекрыть элемент в фокусе
  (WCAG 2.2 «focus not obscured»).
- Поиск показывается, только когда правил больше пяти.
- Escape закрывает раскрытую форму добавления, а не окно.

## 5. Options

- Полная страница: то же, что в popup, плюс экспорт/импорт, сброс правил и очистка подсказок — редкие операции, которым нужно место.
- Список правил, операции над ним и блок статуса — общие с popup модули (`ui/rules-list.js`, `ui/status.js`); оформление — `ui/theme.css`. Дублировать их между двумя поверхностями нельзя: инварианты набора обязаны совпадать.
- Список: сортировка (алфавит предмета, «все» выше конкретных ФИО), поиск-фильтр по subject, счётчик «N/100» (при 100 добавление блокируется).
- Добавление вручную: свободный ввод ФИО + подсказка «введите ФИО точно как в расписании» (подсказки — §11.2) + выбор вида занятия `<select id="rh-type">` (варианты строит `fillTypeSelect` из `PAIR_TYPES`, первый — «Все занятия»). Вторая строка правила в списке — `scopeLabel`: «Иванов И. И. · лекции».
- Все записи — через общий `lib/rules.js` (единый формат, валидация, дубликаты/поглощение, обработка `lastError`).
- «Сброс к дефолту» — с подтверждением, сбрасывает только `rules` (не трогает `enabled`/`style`).
- Экспорт/импорт правил (JSON): выгрузка — `Blob` + `URL.createObjectURL` + `<a download>`, целиком в браузере (ни сети, ни права `downloads`); загрузка — `<input type="file">` + `FileReader`. В файл попадают только правила: тумблер и стиль — нет.
- Импорт проводит каждое правило файла через тот же `planAdd`, что и ручное добавление (`planImport` — чистая функция), поэтому инварианты набора те же. Разрушительный импорт (замена набора или поглощение существующих правил) требует подтверждения: `importRules` без `confirmed: true` возвращает `status: 'confirm'` со сводкой — та же схема, что `addRule` с `autoAbsorb`. Не помещающийся в лимит импорт отклоняется целиком (`status: 'limit'`, `fits`), а не выполняется наполовину.
- Два независимых блока статуса (список правил и экспорт/импорт) — общая фабрика `createStatus`.
- Подсказки при ручном вводе: два `<datalist>`, наполняются из `chrome.storage.local` (`lib/suggestions.js`); обновляются по `storage.onChanged` с `area === 'local'` — расписание могли открыть уже после настроек. Кнопка «Очистить подсказки» обнуляет оба списка.
- Тёмная тема и все прочие цвета — токены в `ui/theme.css`; тёмный набор переопределяет их по `prefers-color-scheme`, отдельного переключателя нет. `color-scheme: light dark` нужен, чтобы штатные контролы (чекбоксы, радио, диалог выбора файла) тоже стали тёмными.
- `tests/ui.test.js` проверяет то, что глазами не увидишь: тёмный набор переопределяет ровно те же переменные, что светлый; все использованные переменные объявлены; цвета не захардкожены мимо переменных; контраст в обеих темах не ниже порога; `[hidden]` перебивает `display:flex`; кольцо фокуса нигде не снято без замены; каждое поле подписано; кнопка-иконка имеет `aria-label`; в разметке нет эмодзи вместо иконок.

## 6. Тестируемость

- `matcher.js` пишется без зависимостей от chrome/DOM; тесты на Node с простыми моками элементов.
- Все девять наборов (`matcher`, `rules`, `content`, `background`, `options`, `suggestions`, `ui`, `popup`, `manifest`) используют один формат: реестр именованных тестов, провал называет сценарий и не обрывает остальные, в конце — счётчик и код выхода.
- Мок `chrome.storage.sync` в `rules.test.js` соблюдает квоту на ключ (8192 байта UTF-8), как Chrome: тест «сотое правило с длинными названиями» без хранения частями падает.
- Мок DOM в `content.test.js` связывает инлайн-стиль с атрибутом `style` (как CSSOM): так проверяется, что у полностью скрытой клетки инлайновый фон снят, а не подменён.
- Вид занятия: правило с видом скрывает только свой вид; правило без вида (v1.0) — все; `ruleMatchesPair` и `matchRule` совпадают на сетке правил и пар; покрытие, поглощение и пересечение; «Вернуть» с несколькими правилами — только после подтверждения.
- Тест-кейсы: 1 пара; 2 пары через `<hr>`; 3 пары (2 скрываемые + 1 нет); пара без названия (ОВ/ОС) не скрываема; точное совпадение с подгруппами (A1.1 ≠ B1); «у всех» vs «конкретный преподаватель»; нормализация пробелов/NBSP; выключенные правила; одна пара с двумя преподавателями через `<hr>` внутри группы (встречается на сайте: «ПР Преп1 <hr> Преп2») — группа не разбивается, `<hr>` прикрепляется к паре, правило по преподавателю скрывает **только его блок** (поблочно), «у всех» / оба преподавателя скрывают пару целиком (одна «скрыто», шапка скрывается), плейсхолдеры игнорируются в структуре пар.

## 7. Безопасность и соответствие CWS

- `permissions: ["storage"]` только.
- Нет `host_permissions` (content_scripts.matches достаточно; сеть не используется).
- Нет eval/remote code; всё внутри пакета.
- Content script не отправляет данные наружу; в SW — только счётчик для бейджа.
- DOM-изменения только со стороны content script; SW не имеет доступа к DOM страницы.
