# Rasp Hide — требования

> Статус: зафиксировано. Версия продукта: 1.0 (первый релиз, пишется с нуля; текущий прототип — не в счёт).
> Публикация: Chrome Web Store + open-source на GitHub (лицензия MIT).

## 1. Назначение

Расширение скрывает пары в расписании ТПУ (`https://ro-rasp.tpu.ru/*`) по выбору пользователя.
Не привязано к иностранным языкам: скрывать можно **любые** пары (предмет, преподаватель или оба признака).

## 2. Целевые страницы

- Работает на **любых** страницах сайта, содержащих `#raspisanie-table` (группа, преподаватель, аудитория), включая архивные (`is_archive=1`).
- Ограничено строго доменом `https://ro-rasp.tpu.ru/*`.

## 3. Основной сценарий

1. Пользователь открывает расписание.
2. Наводит курсор на пару → появляется кнопка «Скрыть» (при hover).
3. Клик по кнопке → мини-меню:
   - «Скрыть у этого преподавателя» — скрывает пары с этим названием **и этим ФИО**;
   - «Скрыть у всех преподавателей» — скрывает пары с этим названием у любого преподавателя;
   - «Отмена».
4. Пара скрывается, на её месте появляется бледный плейсхолдер «скрыто».
5. При hover на плейсхолдер появляется кнопка «Вернуть» — пара возвращается, правило удаляется. Благодаря инварианту поглощения (п. 4) подходящее включённое правило всегда одно; защитно — удаляется самое специфичное (с преподавателем), «у всех» — только если специфичного нет.
6. Правила также видны и управляемы на странице настроек (вкл/выкл, удаление).

## 4. Матчинг пар

- **Точное совпадение** видимого короткого названия предмета (текст `<span>` в клетке).
  - Подгруппы **не** группируются: `АЯ д/акад.целей.A1.1` и `АЯ д/акад.целей.B1` — разные правила.
- Перед сравнением текст нормализуется: trim, схлопывание пробелов и `&nbsp;`.
- Дополнительный признак правила — преподаватель:
  - `teacher: null` — «у всех преподавателей»;
  - `teacher: "ФИО"` — только у конкретного преподавателя (по видимому ФИО).
- Пары **без названия предмета** (ОВ — онлайн-выбор, ОС — организационное собрание и т.п.) скрытию **не подлежат** и в hover-UI не участвуют.
- Если в клетке несколько пар — обрабатываются и скрываются независимо (скрытая пара → плейсхолдер, остальные пары не затрагиваются).
- Одна пара с несколькими преподавателями (`ПР Преп1 <hr> Преп2` — на сайте это одна пара на одно время) скрывается **поблочно**: правило «у конкретного преподавателя» скрывает только его блок (`[Преп N ...]` с идущим перед ним `<hr>`), остальные блоки и название пары остаются видимыми. Название пары (шапка) скрывается, когда скрыты **все** блоки пары (например, правилом «у всех»).

### 4.1. Инварианты набора правил

Поддерживаются при **любом** изменении набора (hover-меню и options — единая логика, см. ARCHITECTURE `lib/rules.js`):

- **Дубликаты запрещены**: правило с тем же предметом и тем же признаком преподавателя (вкл или выкл) не создаётся — «Правило уже существует», предлагается включить существующее.
- **Поглощение**: добавление/включение широкого правила (`teacher: null` — «у всех») удаляет включённые узкие правила того же предмета. Никогда не тихое: перед удалением показывается список удаляемых правил, требуется подтверждение (в hover-меню и в options).
- **Узкое правило при активном «у всех»** того же предмета добавить нельзя — «Уже покрыто правилом „X — все преподаватели"» + [Включить существующее].
- Матчинг преподавателя — по видимому ФИО («Фамилия И. Я.») с нормализацией; id `/user_...` не используется (осознанный компромисс: пользователи видят только ФИО).
- Ручной ввод ФИО — свободный текст с подсказкой «введите ФИО точно как в расписании»; автокомплит — кандидат в v2.

## 5. Визуальное поведение

- **Скрытая пара/блок** — содержимое скрыто, вместо него — плейсхолдер «скрыто» (занимает место). Для пары с несколькими преподавателями плейсхолдер ставится после скрытого блока; при полном скрытии пары (все блоки) — одна «скрыто» на всю пару.
- **Клетка (td)**:
  - только в режиме «плейсхолдер»: если скрыты **все** пары клетки — фон клетки становится цветом пустой клетки (`transparent`), исходный фон восстанавливается при возврате;
  - если осталась хотя бы одна видимая пара — фон клетки **не** трогается;
  - в режиме «зачеркнуть» фон клетки **не трогается никогда** (пара формально остаётся видимой).
- Стиль скрытия (пусто/плейсхолдер) — глобальный, настраивается. Вариант «зачеркнуть/затемнить» допустим, но плейсхолдер — основной.
- Изменения в DOM сайта (перерисовка таблицы, расшифровка названий) — применяются автоматически (MutationObserver с дебаунсом).

## 6. Интерфейс

### 6.1. На странице расписания (content script)

- Кнопка «Скрыть» — появляется при hover на паре, не перекрывает клики по ссылкам (преподаватель, аудитория).
- Мини-меню: у пары с одним преподавателем — «Скрыть: ФИО» / «Скрыть у всех преподавателей» / «Отмена»; у пары с несколькими преподавателями — **отдельный пункт «Скрыть: ФИО» на каждого преподавателя** пары + «у всех» + «Отмена»; для пары **без** преподавателя — один пункт «Скрыть пару» (эквивалент «у всех»).
- Если «Скрыть у всех» поглощает существующие узкие правила того же предмета — меню превращается в подтверждение со списком удаляемых правил ([Удалить] / [Отмена]).
- Плейсхолдер «скрыто» + кнопка «Вернуть» при hover.

### 6.2. Страница настроек (options)

- Глобальный переключатель вкл/выкл.
- Стиль скрытия (плейсхолдер / зачеркнуть).
- Список правил:
  - строка: название предмета + преподаватель (или «все») + вкл/выкл + удалить;
  - сортировка: по алфавиту предмета, «все преподаватели» выше конкретных ФИО;
  - поиск-фильтр по названию предмета (contains, фильтрует на лету);
  - добавление вручную (название + преподаватель/все) — со всеми инвариантами п. 4.1;
  - лимит 100 правил, счётчик «N/100»; при 100 добавление блокируется с пояснением;
  - сброс к дефолту — с подтверждением; сбрасывает **только список правил** (тумблер и стиль не трогаются).
- Ошибка записи в хранилище → сообщение «Не удалось сохранить»; данные не теряются.
- Дефолтный список правил при установке: **пустой** (universal, без языкового набора).

### 6.3. Кнопка в тулбаре

> Изменено в §11.4: клик открывает popup, тумблер переехал внутрь него
> и на горячую клавишу. Бейдж работает как описано ниже.

- ~~Клик — вкл/выкл скрытия (тумблер).~~ (см. §11.4)
- Бейдж — **per-tab** (каждая вкладка со своим состоянием):
  - включено → зелёная цифра счётчика скрытых пар текущей страницы (в т.ч. зелёный «0», если скрытых нет);
  - выключено → серый «OFF»; текст «ON» не используется (цвет и цифра его заменяют);
  - обновление — через `chrome.runtime.sendMessage` из content script (`sender.tab.id`); при уходе вкладки с сайта бейдж очищается.

## 7. Хранилище

- `chrome.storage.sync` (перенос между устройствами). Правила + глобальные настройки.
- Формат правила: `{ subject: string, teacher: string | null, enabled: boolean }`.
- `subject` — видимое короткое название; `teacher: null` = «у всех».
- Все записи — через общий модуль `lib/rules.js`; `chrome.runtime.lastError` обрабатывается: при отказе записи пользователь видит ошибку, данные не теряются.
- Лимит `sync` — 8192 байта на элемент; фиксированный лимит 100 правил гарантирует запас.

## 8. Нефункциональные требования (модерация CWS)

- Только Manifest V3.
- **Минимальные права**: `permissions: ["storage"]`; `host_permissions` **не** указывается (для `content_scripts.matches` он не нужен, сетевых запросов нет).
- Запрещены `eval()`, `new Function()`, `setTimeout/setInterval` со строковыми аргументами, внешние `<script src>` и удалённый код.
- Весь сетевой код (если появится) — только в `background.js` (service worker); content script не ходит в сеть.
- Секреты/ключи/адреса в коде не хардкодятся; если появятся — ввод через options + `chrome.storage.local`.
- Код читаемый, без обфускации; минификация допустима.
- Никаких данных пользователя наружу не отправляется (для CWS: «no data collection»).
- Все DOM-взаимодействия — в content script; SW и options не трогают страницу.
- Язык интерфейса — русский, хардкодом; `chrome.i18n`/`_locales` в v1 не используется.

## 9. Разработка и качество

- Чистая логика (группировка пар, матчинг) выносится в отдельный модуль, тестируемый вне браузера (Node, без DOM-зависимостей где возможно).
- Юнит-тесты на матчинг и группировку.

## 11. Реализовано после v1.0

Пункты из §10, вынесенные в работу отдельно. Контракт v1.0 (§1–9) они не меняют:
права остаются `["storage"]`, сеть не используется, язык — русский хардкодом.

### 11.1. Экспорт и импорт правил (JSON)

- Экспорт: кнопка на странице настроек сохраняет файл `rasp-hide-rules-ГГГГ-ММ-ДД.json`
  целиком в браузере (`Blob` + `URL.createObjectURL` + `<a download>`); ни сети,
  ни права `downloads` не требуется. В файл попадают **только правила** — тумблер
  и стиль скрытия не экспортируются.
- Формат: `{ format: "rasp-hide-rules", version: 1, exportedAt, rules: [...] }`;
  `version` — версия структуры файла, не расширения. При разборе принимается также
  голый массив правил.
- Импорт: два режима — слияние (по умолчанию) и замена набора.
  - Каждое правило из файла проходит **те же инварианты** п. 4.1, что и ручное
    добавление: дубликаты и уже покрытые пропускаются, широкое правило поглощает
    узкие, лимит 100 действует.
  - Разрушительный импорт (замена непустого набора или поглощение существующих
    правил) выполняется **только после подтверждения**: сначала показывается сводка
    с перечнем удаляемых правил.
  - Не помещающийся в лимит импорт отклоняется **целиком**, с указанием, сколько
    правил поместилось бы: половинчатый набор непредсказуем для пользователя.
  - Записи файла, не проходящие валидацию (пустой предмет, не объект), отбрасываются
    и импорт не роняют.
- Ошибка записи в хранилище → «Не удалось сохранить», текущий набор не теряется.

### 11.2. Подсказки предметов и ФИО при ручном вводе

Обещанный в п. 4.1 автокомплит.

- Content script запоминает **видимые** названия пар и ФИО с открытых страниц
  расписания; поля ручного добавления правила предлагают их через `<datalist>`.
- Хранилище — `chrome.storage.local`, ключ `suggestions`. Именно `local`, а не `sync`:
  это кэш увиденного, а не настройка; между устройствами он не переносится.
- Данные никуда не отправляются. В настройках есть кнопка «Очистить подсказки».
- Потолок — 500 записей в каждом списке; при переполнении свежие вытесняют старые.
- Запись только при реальном изменении набора: прогон расписания идёт по дебаунсу
  и не должен дёргать хранилище на каждую перерисовку таблицы.
- Ошибка записи подсказок не показывается пользователю: это удобство, а не его данные.
  Сами правила по-прежнему сообщают об ошибке записи («Не удалось сохранить»).
- При выключенном тумблере прогона нет — и сбора подсказок нет.
- Подсказка остаётся подсказкой: поле ввода свободное, значение из списка выбирать
  не обязательно (п. 4.1 не меняется).

### 11.3. Тёмная тема страницы настроек

- Только страница настроек. На страницу расписания тема не распространяется:
  сайт светлый, и перекрашивать его содержимое расширение не должно.
- Следует настройке системы (`prefers-color-scheme`), отдельного переключателя нет —
  лишняя настройка там, где ответ уже известен браузеру.
- Цвета вынесены в CSS-переменные; тёмный набор переопределяет **тот же** набор
  переменных (проверяется тестом — забытая переменная означала бы невидимый текст).
- `color-scheme: light dark` — чтобы штатные контролы (чекбоксы, радио, диалог
  выбора файла, скроллбары) тоже следовали теме.
- Контраст текста проверяется тестом в обеих темах: обычный текст — не ниже 4.5,
  приглушённый (выключенное правило) — не ниже 3.0.

### 11.4. Popup как основная поверхность

Клик по иконке открывает окно расширения. Это меняет п. 6.3: `chrome.action.onClicked`
при заданном `default_popup` не срабатывает вовсе, поэтому тумблер переехал в popup.

- **Цена решения**: раньше выключение стоило одного клика, теперь двух. Взамен
  добавлена команда `toggle-hiding` (по умолчанию `Alt+Shift+H`, переназначается
  на `chrome://extensions/shortcuts`) — выключение снова в одно движение, уже без
  попадания мышью в иконку. `commands` — ключ манифеста, не разрешение: список
  `permissions` остаётся ровно `["storage"]`.
- **Что в popup**: тумблер, состояние текущей вкладки, список правил с поиском,
  добавление вручную (раскрывается по кнопке), вид скрытой пары, кнопка на полную
  страницу настроек.
- **Что осталось только на полной странице**: экспорт/импорт, сброс правил,
  очистка подсказок — редкие операции, которым нужно место и внимание.
- **Состояние вкладки** берётся из текста бейджа (`chrome.action.getBadgeText`),
  который content script уже выставил: это ровно то же число, и читается оно без
  права `tabs`. Фраза собирается целиком («Скрыто пар на этой странице: 3»),
  а не из числа отдельно — скринридер должен получить законченное предложение.
- **Поиск** появляется, только когда правил становится больше пяти: над коротким
  списком это лишний элемент управления.
- Список правил и все операции над ним — общий модуль (`ui/rules-list.js`):
  инварианты набора обязаны совпадать на обеих поверхностях и в меню на расписании.

### 11.5. Оформление интерфейса

Общее для popup и настроек, вынесено в `ui/theme.css`.

- Стиль — минимализм: плотная сетка, высокий контраст, никаких декоративных
  эффектов. Акцент — teal `#0d9488`.
- **Контраст проверяется тестом** в обеих темах: обычный текст ≥ 4.5,
  приглушённый и нетекстовые элементы (кольцо фокуса) ≥ 3.0. Белый текст на
  акцентной заливке даёт 3.74 и для 13px не годится — поэтому на ней текст тёмный.
- **Шрифт системный.** Пара из подобранной дизайн-системы (Plus Jakarta Sans)
  подключалась бы с Google Fonts — внешние ресурсы расширению запрещены (п. 8),
  а тащить файлы шрифта в пакет ради окна 380px несоразмерно.
- **Иконки** — инлайновый SVG в манере Phosphor, одна толщина штриха, сетка 24.
  Эмодзи вместо иконок не используются: они разъезжаются по платформам и не
  наследуют цвет текста. Проверяется тестом.
- **Фокус** виден на всех управляющих элементах; там, где сам `input` визуально
  скрыт (переключатель, сегментный выбор), кольцо перенесено на видимого соседа.
  Тест не даёт снять `outline` без такой замены.
- **Каждое текстовое поле подписано** видимым `<label>`: плейсхолдер подписью
  не является — он исчезает при вводе. Проверяется тестом.
- **Кнопка без видимого текста** обязана иметь `aria-label`. Проверяется тестом.
- Блоки статуса объявлены `role="status" aria-live="polite"`; фокус при показе
  сообщения не перемещается.
- Движение — только `transform`/`opacity`, 110–160 мс, полностью снимается
  по `prefers-reduced-motion`.
- Подтверждения разрушительных действий показываются в самом интерфейсе, а не
  через `window.confirm`: системный диалог в popup выглядит чужеродно и на части
  платформ закрывает само окно.
