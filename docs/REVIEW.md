# Rasp Hide — ревью кодовой базы (v1.0.0)

> Ревью состояния на теге `v1.0.0` (коммит `1ffd7eb`). Документ описательный:
> контракт в `REQUIREMENTS.md` / `ARCHITECTURE.md` / `PLAN.md` не меняет.
> Каждая находка помечена веткой, в которой она исправляется.

## 0. Общая оценка

Проект соответствует собственному контракту: MV3, `permissions: ["storage"]`,
без `host_permissions`, без `eval`/удалённого кода, весь UI с префиксом `rh-*`,
81 именованный тест в `matcher`/`rules`/`content` плюс набор проверок в
`background.test.js`, CI на Node 22. Логика правил централизована в
`lib/rules.js`, инварианты (дубликаты, поглощение, «уже покрыто», лимит 100)
реализованы одним набором чистых функций и используются и hover-меню, и options —
это главное архитектурное решение проекта, и оно выдержано.

Ниже — то, что не выдержано.

## 1. Дефекты

### 1.1. `processCells()` не проверяет тумблер — «полускрытое» состояние после OFF

**Файлы:** `content/content.js:189` (`processCells`), `content/content.js:265`
(`fullRollback`), `content/content.js:372` (MutationObserver).
**Нарушает:** REQUIREMENTS §3.4 — «Никакого „полускрытого" состояния».
**Ветка:** `claude/fix/rollback-and-guards`.

`MutationObserver` планирует `processCells` через `setTimeout(…, 120)`. Проверка
`if (!settings.enabled) return;` стоит **в обработчике мутации**, то есть в момент
планирования, а не в момент срабатывания. `fullRollback()` таймер не снимает, и сам
`processCells()` тумблер не смотрит вообще.

Сценарий: сайт перерисовывает таблицу (или пользователь наводит курсор) → запланирован
прогон; в течение 120 мс пользователь жмёт иконку → `storage.onChanged` → `fullRollback()`
чистит `rh-*` и стили → через оставшиеся миллисекунды срабатывает «протухший» таймер →
пары снова скрываются, плейсхолдеры возвращаются, в SW уходит `{type:'count'}` и бейдж
становится зелёной цифрой при выключенном расширении.

Воспроизводится напрямую на моках: после `loadSettings()` с `enabled: false` вызов
`processCells()` скрывает пару (`display:none`), вставляет плейсхолдер и шлёт
`{type:'count', value:1}`.

**Исправление:** ранний выход по `settings.enabled` в самом `processCells` +
`clearTimeout(debounceTimer)` в `fullRollback`.

### 1.2. `position: relative` протекает в «исходный» стиль клетки и остаётся после OFF

**Файлы:** `content/ui.js:204` (`ensureCellPosition`), `content/content.js:28..43`
(`cacheCellStyle` / `restoreCellStyle`), `content/content.js:170` (`updateCellBackground`).
**Нарушает:** REQUIREMENTS §3.4 — «исходные стили восстанавливаются».
**Ветка:** `claude/fix/rollback-and-guards`.

`ensureCellPosition` пишет `cell.style.position = 'relative'` — это меняет атрибут
`style` клетки. Порядок в `processCells`: `cacheCellStyle` (кэш исходного атрибута) →
… → `updateCellBackground` → `restoreCellStyle`, который восстанавливает атрибут **и
удаляет запись из `WeakMap`**. `UI.syncHover` отрабатывает уже после и снова ставит
`position: relative`.

Итог: на следующем прогоне `cacheCellStyle` кэширует стиль, в котором `position: relative`
уже есть, — служебное свойство расширения записывается в «исходный» стиль навсегда.
После `fullRollback` клетки остаются с `position: relative` (а если последний прогон
закончился на `restoreCellStyle`, записи в `WeakMap` уже нет и откат стиля вообще не
выполняется).

**Исправление:** не трогать инлайн-стиль клетки — позиционировать через класс
`rh-cell` из внедряемой таблицы стилей и снимать класс при откате.

### 1.3. Присваивание `chrome.runtime.lastError = null`

**Файлы:** `lib/rules.js:188`, `options/options.js:56`.
**Ветка:** `claude/fix/rollback-and-guards`.

`chrome.runtime.lastError` — свойство, которым владеет рантайм: Chrome выставляет его
перед вызовом коллбэка и снимает сам, как только коллбэк вернул управление. Достаточно
его **прочитать** (чтение и гасит предупреждение «Unchecked runtime.lastError»); запись
API не предусмотрена и в строгом режиме зависит от того, как биндинги определяют
свойство. Обе строки — лишние, но при этом критичные: обёрнуты они в `Promise`, и
исключение из коллбэка привело бы к тому, что промис никогда не разрешится, а
пользователь не увидит «Не удалось сохранить».

Побочный эффект: моки в `tests/rules.test.js` и `tests/background.test.js` `lastError`
сами не сбрасывают и опираются на то, что его снимет продакшн-код, — то есть моделируют
Chrome неверно. Мок нужно привести к реальной семантике (снимать после возврата из
коллбэка), а присваивания из продакшн-кода убрать.

### 1.4. Меню без кнопки после неудачного «Вернуть»

**Файл:** `content/ui.js:744` (`doRestore`).
**Ветка:** `claude/fix/rollback-and-guards`.

```js
const res = await R.restorePair(pm.name, teacher);
hideController(c);                       // прячет и кнопку, и меню
if (res.status === 'none') renderStatus(c, 'Не найдено правило для возврата');
```

`renderStatus` заново показывает меню (`menu.classList.add('rh-visible')`), но кнопка
уже скрыта: сообщение об ошибке висит без якоря. `hideController` нужно вызывать
только на успешной ветке.

### 1.5. Кнопка создаётся с текстом «Скрыть», показывается как «Скрыть ▾»

**Файл:** `content/ui.js:480` vs `content/ui.js:303`. Косметика; текст задаётся дважды
в двух вариантах. **Ветка:** `claude/fix/rollback-and-guards`.

## 4. Что проверено и претензий не вызвало

- **Инварианты правил** (`lib/rules.js`): `planAdd` корректно упорядочивает
  `duplicate` → `covered` → `absorb` → `limit`; лимит считается по итоговому размеру
  набора *после* поглощения, поэтому «100 правил + широкое, поглощающее три» проходит.
- **Поблочное скрытие**: `splitPairIntoBlocks` отдаёт `<hr>` следующему блоку, шапка
  скрывается только при `allHidden` — соответствует PLAN §3.
- **Идемпотентность прогона**: ключ контроллера — DOM-узел шапки, а не массив пары
  (иначе `MutationObserver` зацикливался бы), `syncPlaceholders` не плодит дубликаты.
  Собственные мутации отфильтровываются `isRhMutation`, атрибуты не наблюдаются.
- **CWS-ограничения**: `eval`/`new Function`/строковых таймеров/внешних скриптов нет,
  `permissions` ровно `["storage"]`, сети нет, префикс `rh-*` выдержан.
- **Бейдж**: per-tab, зелёная цифра (включая «0»), серый «OFF»; `handleMessage`
  игнорирует сообщения без `sender.tab.id`.

## 6. Идеи вне этой работы

- **CI**: `on: push` ограничен ветками `main`/`dev` — на `claude/*` и любых фича-ветках
  тесты в CI не гоняются, зелёными их видит только merge-request. Разумно снять фильтр
  веток у `push`.
- **Линтер**: линтера/форматтера нет осознанно (AGENTS.md), но `eslint --no-eslintrc`
  с парой правил (`no-unused-vars`, `eqeqeq`) поймал бы мёртвый код из §2 бесплатно.
- **Клавиатура**: hover-UI доступен только мышью — кнопка «Скрыть» не получает фокус.
  Требованиями не предусмотрено, но это реальный барьер.
- **`tests/background.test.js` выбивается из общего стиля**: вместо именованных тестов —
  сплошные `assert`-блоки, поэтому `npm test` не печатает по нему счётчик, а первый же
  провал обрывает файл сырым стеком без имени сценария. Плюс `makeStorage` объявляет
  `_failNextSet` на внешнем объекте, а читает `this._failNextSet` внутри `sync.set` —
  работает только потому, что тест выставляет флаг напрямую на `storage.sync`.
- **`ui.js` — 771 строка**: стили, позиционирование, hover-машина состояний, меню и
  действия над правилами в одном файле. Разделение напрашивается, но это большой
  риск регресса на живом hover-UI — отдельной задачей, с ручной проверкой.
