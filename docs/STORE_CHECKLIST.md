# Rasp Hide — чек-лист модерации магазинов расширений и публикации

Магазины: Chrome Web Store (CWS), Firefox Add-ons (AMO), Edge Add-ons, Opera Add-ons.
Пакет один на все (REQUIREMENTS §11.11); разделы 1–2 и 5 общие, раздел 3 — по магазинам.

## 1. Код (обязательно перед сабмитом)

> Манифест, права, файлы пакета, eval/строковые таймеры, удалённый код, сеть и внешние
> ресурсы проверяет `tests/manifest.test.js` (входит в `npm test`) — по этим пунктам
> отметка ставится по зелёному прогону. Читаемость кода и префикс `rh-*` — глазами.

- [ ] `manifest.json` — только MV3.
- [ ] `permissions` ровно `["storage"]`, без лишнего.
- [ ] Нет `host_permissions` (не используется сеть; для `content_scripts.matches` не требуется).
- [ ] Ключи браузеров на месте: `background.scripts` = тот же файл, что `service_worker`; `minimum_chrome_version` ≥ 121; `browser_specific_settings.gecko` — `id`, `strict_min_version`, `data_collection_permissions: { required: ["none"] }`. `gecko.id` после первой публикации в AMO не менять.
- [ ] `npx web-ext lint` — 0 ошибок (предупреждения про игнорируемый `service_worker` и про Android — ожидаемые).
- [ ] Нет `eval()`, `new Function()`, строковых `setTimeout`/`setInterval`, `unsafe-eval` в CSP.
- [ ] Нет внешних `<script src>`, удалённого кода, CDN.
- [ ] Вся логика — внутри пакета; файлы подключены в манифесте.
- [ ] Нет внешних шрифтов и иконочных наборов: шрифт системный, иконки — инлайновый SVG.
- [ ] Нет обфускации; код читаемый, с комментариями-документацией.
- [ ] Нет хардкода ключей/токенов/адресов локальных сервисов (не актуально для v2, но правило).
- [ ] Сеть (если появится) — только из `background.js`; content script не ходит в сеть.
- [ ] Никакой отправки пользовательских данных наружу.
- [ ] Нет конфликтов с DOM сайта (префикс `rh-*` у добавляемых элементов, аккуратная очистка).

## 2. Хранилище и приватность

- [ ] `chrome.storage.sync` — только настройки расширения (правила частями `rules`, `rules_1..3`, тумблер, стиль); `chrome.storage.local` — только подсказки для ручного ввода.
- [ ] Все записи через `lib/rules.js` с обработкой `chrome.runtime.lastError` (ошибка → «Не удалось сохранить», данные не теряются).
- [ ] Заявка в CWS: «This extension does not collect any data» (никакого сбора, аналитики, телеметрии). Тексты для вкладки Privacy practices — `docs/STORE_LISTING.md`.
- [ ] Privacy policy URL — ссылка на `PRIVACY.md` в публичном репозитории (поле обязательно для завершения вкладки Privacy practices).
- [ ] AMO, Edge, Opera: то же заявление — данные не собираются; в AMO оно берётся из манифеста (`data_collection_permissions`), в формах Edge и Opera — ссылка на `PRIVACY.md`.

## 3. Формы магазинов

Тексты одни на все магазины — `docs/STORE_LISTING.md`. Лимиты полей и размеры картинок
у магазинов меняются: сверять с формой в день сабмита.

### 3.1. Chrome Web Store

- [ ] Название витрины = `name` манифеста (≤ 75 символов). Сейчас «Rasp Hide»; для поиска по «расписание ТПУ» — решить, менять ли на «Rasp Hide — скрытие пар в расписании ТПУ».
- [ ] Краткое описание = `description` манифеста (≤ 132 символа, проверяется тестом).
- [ ] Подробное описание, категория, single purpose, обоснование прав и доступа к сайту — готовые тексты в `docs/STORE_LISTING.md`.
- [ ] Язык интерфейса и листинга — русский (i18n нет).
- [ ] **Обязательные картинки** (без них форма не отправится):
  - [ ] иконка 128×128 в пакете (есть; по гайдлайну CWS — рисунок 96×96 с прозрачными полями 16px, текущая иконка — сплошной квадрат из прототипа);
  - [ ] минимум 1 скриншот 1280×800 (или 640×400), лучше 3–5: расписание с hover-кнопкой, меню «Только лекции | Все занятия», скрытые пары с плейсхолдером, popup, настройки;
  - [ ] малая промо-картинка 440×280 (обязательна).
- [ ] Права: заявить только `storage` (выводится автоматически из манифеста; лишнего не заявлять). Доступ к сайту (`content_scripts.matches`) — тоже требует обоснования, текст в `docs/STORE_LISTING.md`.

### 3.2. Firefox Add-ons (addons.mozilla.org)

- [ ] Исходники отдельно не прикладываются: кода после сборщика или минификатора в пакете нет.
- [ ] Название, краткое и подробное описание, категория, лицензия MIT, политика конфиденциальности, заметка для проверяющего — `docs/STORE_LISTING.md`.

## 5. Финальная проверка перед сабмитом

- [ ] `npm run pack` → `dist/rasp-hide-<версия>.zip`; распаковать архив в пустую папку и установить **его** как распакованное расширение (проверяется ровно то, что уйдёт в магазин).
- [ ] Установка «распакованное расширение» в Chrome/Arc из свежей копии репо.
- [ ] Firefox: `npx web-ext run --source-dir . --start-url https://ro-rasp.tpu.ru/` (или `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» → `manifest.json`); все пункты ниже повторяются в нём. Отдельно: расширение работает сразу после установки (доступ к сайту выдан), стили `rh-*` применились, экспорт скачивает файл.
- [ ] Edge (и по возможности Opera, Яндекс Браузер): распакованное расширение ставится без ошибок, пункты ниже — выборочно (бейдж, горячая клавиша, скрытие, настройки).
- [ ] Проверка на реальных страницах: группа, преподаватель, аудитория, архив.
- [ ] Тумблер в popup и горячей клавишей (`Alt+Shift+H`), per-tab бейдж (две вкладки: счётчик и «OFF» не «залипают»), зелёный «0» при включённом расширении без скрытых пар.
- [ ] Popup: строка состояния совпадает с бейджем; список, поиск (от 6 правил), добавление, вид скрытой пары, переход на полную страницу.
- [ ] Обе поверхности в светлой и тёмной теме системы; проверка с клавиатуры (Tab по всем элементам, видимое кольцо фокуса, Escape закрывает форму добавления).
- [ ] Плейсхолдер, hover-возврат, список правил в настройках.
- [ ] Инварианты правил: дубликат блокируется; «у всех» поглощает узкие с подтверждением; узкое при активном «у всех» блокируется; лимит 100 («N/100»).
- [ ] Вид занятия: в меню лекции — «Только лекции» выбрано по умолчанию, скрывается только лекция, практика того же предмета остаётся; «Все занятия» скрывает обе; «Матан — все» поглощает «Матан (ЛК) — все» с подтверждением; при пересечении («у Иванова» + «лекции у всех») «Вернуть» показывает список и подтверждение.
- [ ] Popup и настройки: поле «Вид занятия», вторая строка правила «ФИО · вид», правила v1.0 показаны как «все занятия».
- [ ] Hover: навести на пару → на кнопку → увести курсор из клетки — кнопка пропадает (~0,3 с); открыть меню → увести курсор — меню пропадает (~1 с); в клетке курсор кнопку и меню не теряет.
- [ ] Фон: скрыть все пары в клетке **текущего** дня — клетка остаётся светло-зелёной (`#e8f5e9`), в другие дни — белой; «Вернуть» — исходный цвет пары.
- [ ] Обновление с v1.0: правила, созданные в v1.0, на месте и работают как «все занятия».
- [ ] Полный откат при OFF: все `rh-*` удалены, фоны восстановлены, hover-UI не работает.
- [ ] Перезагрузка страницы — скрытие сохраняется и применяется.
- [ ] Синк правил между профилями одного браузера (если есть возможность проверить); между разными браузерами — экспорт и импорт.
- [ ] `npm test` — зелёный (9 наборов).
- [ ] Проверка «второй человек»: чистый профиль Chrome и чистый профиль Firefox, установка, 5 минут использования без ошибок в console и в фоновом скрипте (Service Worker / `about:debugging` → «Исследовать»).
